# SCF 自动提醒诊断增强设计

## 背景

项目当前在线上使用腾讯云 SCF。自动提醒由 SCF 定时触发 `main_handler`，再执行 `runDaily()` 和 `runPrePush()`。现有测试已经覆盖“每日汇总不会提前消费当天一次性提醒，30 分钟前预提醒仍会发送”的场景，因此之前的提醒消费问题大概率已修复。

当前仍存在一个关键盲区：当用户反馈“好几天不会自己提醒”时，无法快速判断原因是 SCF 没触发、Redis 没读到用户或提醒、当前时间未进入推送窗口，还是微信客服消息接口拒绝发送。尤其是当前发送通道使用微信客服消息接口，长期未互动用户可能触发 `45015` 客服窗口过期。

## 目标

本次改进的目标是让 SCF 自动提醒链路可诊断：每次运行都能产出结构化摘要，说明任务是否触发、处理了多少用户、发现多少待推送提醒、发送成功多少、失败多少，以及失败原因。

## 非目标

本次不改提醒解析逻辑，不更换微信推送通道，不改变 Redis 数据结构，不删除 Cloudflare Worker 或 Vercel 入口。若诊断结果确认主要问题是 `45015`，再单独设计长期主动提醒通道。

## 方案

### 运行摘要

为定时任务引入 `JobRunSummary` 结果对象。摘要包含：

- 本次运行时间和上海日期。
- `daily` 每日汇总统计。
- `prePush` 提前提醒统计。
- 总用户数。
- 成功发送数。
- 失败发送数。
- 失败明细。

`daily` 部分记录：进入每日推送窗口的用户数、已跳过的用户数、今日提醒数量、成功发送数量、失败数量。  
`prePush` 部分记录：候选提醒数量、因无具体时间跳过的数量、因不在窗口跳过的数量、因已预推送跳过的数量、成功发送数量、失败数量。

失败明细包含阶段、openid、错误消息和可识别的微信错误码。错误码至少识别 `45015`、`40001`、`42001`。

### 数据流

`runDaily()` 和 `runPrePush()` 继续负责原有业务逻辑，但从只返回 `void` 改为返回各自的统计结果。单个用户或单条提醒发送失败时，不中断整个任务；函数记录失败明细后继续处理后续用户。

`runScheduledJobs()` 汇总两个函数的结果并返回整体摘要。Timer 触发时将摘要写入 SCF 日志；API Gateway `/cron` 手动触发时返回 JSON 摘要，便于线上临时诊断。

`/debug` 保持现有职责，只检查环境变量解析和 Redis 连通性，不触发推送，避免误发送。

### 错误分类

`sendText()` 继续在微信接口失败时抛错。上层任务根据错误消息分类：

- `45015`：微信客服消息窗口过期，说明当前通道无法长期主动触达该用户。
- `40001` / `42001`：access token 无效或过期，现有重试仍保留；重试后失败才进入摘要。
- 其他错误：归类为未知微信发送错误或运行时错误。

这样可以把“任务没跑”和“微信拒绝发送”区分开。

## 测试方案

新增或扩展测试覆盖：

1. `runDaily()` 在无用户、有用户但未到推送窗口、进入窗口并发送成功、发送失败时返回正确统计。
2. `runPrePush()` 在候选提醒、重复触发、无具体时间、微信发送失败时返回正确统计。
3. `scf-main.ts` 的 `/cron` 返回 JSON 摘要。
4. Timer 事件中单个用户失败不会导致整体任务失败。
5. `45015` 会被归类为清晰的客服窗口过期失败原因。

## 验收标准

- 手动访问 SCF `/cron` 可以看到结构化 JSON 摘要。
- SCF Timer 触发后日志中可以看到同样的摘要。
- 当微信返回 `45015` 时，摘要明确显示客服窗口过期。
- 现有 53 个测试继续通过。
- TypeScript 类型检查继续通过。
