# 华中师范大学学生提醒体验增强设计

## 背景

当前项目是一个微信日常提醒工具，已经具备添加提醒、批量添加、查看列表、删除提醒、设置每日推送时间、每日汇总推送、30 分钟前预提醒、SCF 定时触发和 `/cron` 诊断摘要等能力。

现有能力可用，但用户体验仍有提升空间：用户不一定知道该怎么输入，输错后主要依赖删除重建，查看提醒的范围不够直观，自然语言解析对学生常见表达支持有限，回复文案也偏通用提醒机器人。

本次优化将项目定位为：面向华中师范大学学生的微信日常提醒与校园生活小助手。第一阶段不接入复杂校园实时数据，而是优先提升提醒交互、确认机制、查看修改能力和华师校园语境文案。

## 目标

- 降低新用户学习成本，让用户知道可以怎样添加、查看、修改、删除提醒。
- 明确输入直接执行，保持日常添加提醒的效率。
- 模糊添加、修改、删除进入确认流程，减少误保存、误改和误删。
- 支持更适合学生日常的查看方式，例如今天、明天、本周、全部、最近提醒。
- 增强常见学生表达解析，例如早八、晚八、本周三、下周五、八点半。
- 回复文案更贴近华中师范大学学生，但不声称具备未接入的实时校园数据。
- 保持现有 SCF 定时提醒、每日汇总、预提醒和 `/cron` 诊断链路独立稳定。

## 非目标

本次不实现以下内容：

- 接入实时课表。
- 接入真实食堂菜单。
- 接入图书馆座位、校车、校园网等实时数据。
- 开放式聊天能力。
- 更换微信推送通道。
- 改造 SCF 定时提醒链路。
- 改变 Redis 中现有提醒主体结构。
- 工作日重复、课程表自动导入、考试周自动推算等复杂能力。

## 用户体验范围

### 帮助文案增强

帮助文案按华师学生常见场景组织，而不是只罗列命令。

示例结构：

- 学习：`明晚8点提醒我交实验报告`、`每周一早上8点提醒我上英语课`、`6月20日提醒我四六级报名`。
- 生活：`下午5点提醒我取快递`、`明天提醒我带伞`、`每天晚上11点提醒我充电`。
- 查看和修改：`查看今天`、`查看本周`、`修改第2条为明天下午3点交作业`、`删除第3条`。
- 设置：`设置每日提醒时间 7:30`。

### 查看提醒增强

支持以下查看方式：

- `查看今天`
- `查看明天`
- `查看本周`
- `查看全部`
- `最近提醒`

列表按时间排序，展示序号、日期、星期、时间、内容和重复规则。列表回复中提示用户可以继续使用 `修改第 N 条为...` 或 `删除第 N 条`。

### 明确添加直接保存

当输入包含明确提醒内容、日期和时间时，直接保存提醒。

示例：

用户：`明天下午3点提醒我交作业`

回复：

```text
记好啦，桂子山打工人 📝
明天 15:00 提醒你：交作业
```

### 模糊添加确认

当添加提醒缺少具体时间、日期时间已经过去、提醒正文为空或过短时，不直接保存，而是进入确认流程。

示例：

用户：`提醒我交作业`

回复：

```text
我理解为：今天提醒你「交作业」。
但你没有说具体时间。
回复“确认”保存，回复“取消”放弃。
```

### 修改提醒确认

支持 `修改第2条为下周五晚上8点交小组作业` 这类命令。修改属于影响已有数据的操作，必须确认后执行。

回复展示原提醒和新提醒：

```text
确认修改第 2 条提醒吗？
原来：周三 10:00 交高数作业
修改为：下周五 20:00 交小组作业
回复“确认”修改，回复“取消”放弃。
```

### 删除提醒确认

删除提醒必须确认后执行。

示例：

用户：`删除第3条`

回复：

```text
确认删除第 3 条提醒吗？
第 3 条：明天 09:00 取快递
回复“确认”删除，回复“取消”保留。
```

## 架构设计

继续沿用当前模块边界，并在现有职责上扩展。

### `parser.ts`

职责：把用户输入解析成结构化命令。

新增或调整：

- 新增 `update` 命令，用于 `修改第 N 条为...`。
- 增强 `list` 命令，支持 `today`、`tomorrow`、`week`、`all`、`recent` 等范围。
- 为添加类解析结果输出模糊原因，例如缺少时间、日期时间已过去、正文过短。
- 解析层不访问 Redis，也不决定是否保存，只描述用户意图和解析结果。

### `store.ts`

职责：Redis 数据读写。

新增：

- `setPendingAction(redis, openid, action)`：保存待确认操作。
- `getPendingAction(redis, openid)`：读取待确认操作。
- `clearPendingAction(redis, openid)`：清除待确认操作。
- `updateReminderById(redis, openid, reminderId, patch)` 或等价更新接口。
- `deleteReminderById(redis, openid, reminderId)`。

按 id 修改和删除可以避免确认期间列表变化导致误操作。

### `router.ts`

职责：微信消息入口与业务编排。

处理顺序：

1. 判断用户是否回复确认词或取消词。
2. 若存在 pending action，则执行或清除。
3. 若没有 pending action，再解析新命令。
4. 明确添加、查看、帮助、设置直接执行。
5. 模糊添加、修改、删除写入 pending action 并回复确认文案。
6. 如果已有 pending action 又收到新命令，不覆盖旧状态，提示用户先确认或取消。

### `formatter.ts`

职责：集中生成用户可读文案。

新增：

- 校园化帮助文案。
- 添加成功文案。
- 模糊添加确认文案。
- 修改确认文案。
- 删除确认文案。
- 确认成功、取消、过期、无 pending action 等状态文案。
- 增强版列表文案。

`router.ts` 不拼接复杂中文，以降低维护成本。

### `types.ts`

新增 pending action 和 ambiguity 类型，保证 parser、router、store、formatter 之间的接口清晰。

## Pending Action 设计

Redis key：

```text
user:{openid}:pending-action
```

TTL：10 分钟。

10 分钟后自动过期，避免用户隔天回复“确认”触发旧操作。

建议类型：

```ts
type AmbiguityReason =
  | "missing-time"
  | "past-time"
  | "empty-text"
  | "short-text";

type PendingAction =
  | {
      kind: "add";
      originalText: string;
      reminder: ParsedReminder;
      ambiguity: AmbiguityReason[];
      createdAt: string;
    }
  | {
      kind: "update";
      originalText: string;
      index: number;
      reminderId: string;
      previous: Reminder;
      nextReminder: ParsedReminder;
      createdAt: string;
    }
  | {
      kind: "delete";
      originalText: string;
      index: number;
      reminderId: string;
      snapshot: Reminder;
      createdAt: string;
    };
```

确认词包括：`确认`、`好`、`好的`、`是的`、`OK`、`ok`。

取消词包括：`取消`、`算了`、`不要了`、`不用了`。

如果用户回复确认词但没有 pending action，回复“目前没有待确认操作”。如果 pending action 已过期，提示用户重新发送提醒或修改命令。

## 模糊判断规则

第一版进入确认的情况：

1. 添加提醒缺少具体时间。
2. 日期时间已经过去。
3. 提醒正文为空或过短。
4. 修改提醒。
5. 删除提醒。

明确添加继续直接保存。

缺少日期但有明确时间时，第一版可以继续沿用默认今天；如果解析后的今天时间已经过去，则进入“日期时间已过去”的确认或错误提示。

## 校园人格化文案

文案风格为：亲切但克制的华师校园助手。

回复可以适度使用华师语境，例如桂子山、南湖、图书馆、自习、早八、期末周，但必须遵守以下边界：

- 不声称知道实时课表、食堂菜单、校车、图书馆座位等未接入数据。
- 不做开放式闲聊。
- 超出能力时，引导用户设置提醒。
- 文案简洁，不刷屏。

轻量场景识别只影响回复语气，不改变提醒时间和业务逻辑。

场景关键词：

- 学习/DDL：作业、论文、ddl、截止、提交、实验报告、复习、考试、四六级、考研。
- 上课：早八、上课、点名、实验课、选修、补课。
- 生活：取快递、洗衣服、拿外卖、买饭、带伞、充电、缴费。
- 活动：社团、开会、例会、志愿、讲座、比赛。
- 图书馆/自习：图书馆、自习、借书、还书、抢座。

## 解析增强

优先增强以下表达：

### 日期

- 今天、明天、后天。
- 本周三、这周三。
- 下周五、下下周一。
- 6月20日、6/20、2026-06-20。
- 月底、下个月1号。

“考试周”“期末周”暂不自动转日期，只作为提醒内容保留。

### 时间

- 早八：08:00。
- 早八半：08:30。
- 晚八、晚上八点：20:00。
- 八点半、8点半：结合上午、下午、晚上等上下文调整；无上下文时按当前规则处理。
- 23:59、晚上11点59。
- 中午12点、下午1点、凌晨1点。

### 重复

- 每天。
- 每周一 / 每星期一。
- 每月15号。

工作日重复不作为第一版范围。

### 命令

- 查看今天、查看明天、查看本周、查看全部、最近提醒。
- 修改第 N 条为……
- 删除第 N 条。
- 设置每日提醒时间 7:30。

## 错误处理

错误文案需要告诉用户下一步怎么做。

示例：

解析不到内容：

```text
我没看懂要提醒什么。
你可以这样说：明天下午3点提醒我交实验报告
```

修改序号不存在：

```text
没找到第 5 条提醒。
回复“查看全部”看看当前有哪些提醒。
```

已有 pending action 时收到新命令：

```text
你还有一个待确认操作。
请先回复“确认”或“取消”。
```

能力之外问题：

```text
这个我现在还查不到实时信息，但可以帮你设个提醒，比如“今晚8点提醒我查课表”。
```

## 数据流

### 添加

1. 用户发送添加提醒消息。
2. `router.ts` 调用 `parser.ts`。
3. 若无模糊原因，直接 `store.addReminder()`。
4. 若存在模糊原因，写入 pending action。
5. 用户确认后再保存。

### 修改

1. 用户发送 `修改第 N 条为...`。
2. `parser.ts` 解析 index 和新提醒。
3. `router.ts` 查询当前提醒列表，找到第 N 条。
4. 写入 pending action，保存 reminder id、旧提醒快照和新提醒。
5. 用户确认后按 reminder id 修改。
6. 清除 pending action。

### 删除

1. 用户发送 `删除第 N 条`。
2. `router.ts` 查询当前提醒列表，找到第 N 条。
3. 写入 pending action，保存 reminder id 和快照。
4. 用户确认后按 reminder id 删除。
5. 清除 pending action。

### 查看

1. 用户发送查看命令。
2. `parser.ts` 解析查看范围。
3. `router.ts` 查询提醒列表并按范围过滤。
4. `formatter.ts` 输出增强列表。

## 与定时提醒链路的关系

确认状态只影响用户主动发消息的交互，不影响：

- `runDaily()`。
- `runPrePush()`。
- `/cron`。
- SCF Timer。

定时提醒链路保持独立，降低回归风险。

## 测试方案

### Parser 单元测试

覆盖：

- `明天下午3点提醒我交作业`。
- `早八提醒我上英语课`。
- `本周三晚上8点开组会`。
- `查看本周`。
- `修改第2条为下周五晚8点交论文`。
- `删除第3条`。
- `设置每日提醒时间 7:30`。

验证 command kind、日期、时间、正文、repeat、ambiguity。

### Store 单元测试

覆盖：

- 保存 pending action。
- 读取 pending action。
- 清除 pending action。
- pending action TTL 参数正确。
- 按 id 修改提醒。
- 按 id 删除提醒。

### Router 流程测试

覆盖：

- 明确添加直接保存。
- 模糊添加进入确认。
- 确认后保存。
- 取消后不保存。
- 修改进入确认，确认后更新。
- 删除进入确认，确认后按 id 删除。
- 有 pending action 时新命令不会覆盖。
- pending 不存在时回复“没有待确认操作”。

### Formatter 文案测试

不需要逐字测试所有中文，但要验证核心信息出现：

- 日期。
- 时间。
- 提醒内容。
- 序号。
- 确认/取消提示。
- 华师校园语气关键文案。

## 验收标准

- 用户能用 `查看今天`、`查看明天`、`查看本周`、`查看全部` 筛选提醒。
- 用户能用 `修改第 N 条为...` 修改提醒，且修改前需要确认。
- 删除第 N 条需要确认。
- 缺少时间、时间已过去或正文异常的添加会进入确认。
- 明确添加仍直接保存，不增加操作步骤。
- 帮助文案面向华中师范大学学生，包含学习、生活、查看、修改、设置示例。
- 回复有校园感，但不夸大能力。
- 现有定时提醒、每日汇总、预提醒和 `/cron` 诊断不受影响。
- 新增测试通过，原有测试继续通过。
